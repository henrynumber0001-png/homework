# Homework 后台管理系统设计文档

> 文档版本：V1.0 Approved
>
> 目标模块：`web/web-admin`
>
> 文档性质：产品范围、业务规则与系统边界设计，不包含接口定义
>
> 评审状态：已于 2026-07-26 确认；接口定义见独立接口文档
>
> 实施范围：本文保留完整产品规则；首期接口按 `web-admin-api.md` V1.1 精简范围实施，低频增强能力延后

## 1. 设计结论

Homework 后台管理系统采用独立管理端、两级管理员、功能权限加数据范围的轻量权限模型。

V1 包含以下六个业务域：

1. 数据看板
2. 内容管理：题库、题目、批量导入与排序
3. 用户与社区治理
4. 会员、订单与套餐管理
5. 管理员与权限管理
6. 操作日志

管理端与用户端共用业务数据库和 `model` 模块，但使用独立登录体系、独立令牌、独立接口命名空间。管理端不得直接复用用户端登录态，也不应依赖 `web-app` 可执行模块。

## 2. 设计目标与范围

### 2.1 目标

- 让运营人员可以安全地管理题库、题目、用户、社区内容和会员。
- 让高风险操作具备明确的授权边界、二次确认和完整审计记录。
- 让批量题目导入具备可预检、可纠错、不可重复提交的稳定流程。
- 让看板指标具有统一口径，可以解释、复算和追溯。
- 在尊重现有数据库模型的基础上完成设计，明确列出必须补充的数据能力。

### 2.2 V1 不包含

- 管理员自助注册。
- 自定义角色设计器；V1 只保留超级管理员和普通管理员。
- 批量创建、批量编辑或批量删除题库。
- 分类树管理；`Group → Module → SubModule` 在 V1 中为只读基础数据。
- 后台“关联已有题目到其他题库”的操作入口；底层数据模型继续保留一题多库能力。
- 判断题、填空题、复合题等当前模型尚未支持的题型。
- 富文本编辑、多图题目和 Excel 内嵌图片解析。
- 用户物理删除、管理员物理删除或业务数据物理删除。
- 任何会员退款；退款能力整体延后到独立版本设计。
- WebSocket 实时看板。

## 3. 现有系统基线

### 3.1 已存在的业务模型

| 业务 | 当前模型 | V1 设计约束 |
| --- | --- | --- |
| 分类 | `category_group`、`category_module`、`category_sub_module` | 题库只保存 `sub_module_id`，Group 和 Module 通过关系反查 |
| 题库 | `question_bank` | 支持单条创建；需要补充明确的业务状态 |
| 面试题 | `question_info` | 当前只支持 `ESSAY` |
| 认证题 | `certificate_question_info` | 当前支持 `SINGLE_CHOICE`、`MULTIPLE`，选项和答案为 JSON |
| 题库与题目关系 | `question_bank_question` | 排序应以关系表的 `sort_order` 为唯一来源 |
| 用户 | `user_info` | 已有 `ACTIVE`、`DISABLED`、`BANNED` |
| 社区 | `hit_post`、`hit_comment` | Post 有业务状态；Comment 缺少统一的业务状态 |
| 会员 | `base_vip_record`、`svip_record` | 分别表示 Premium、Premium Plus 双台账 |
| 套餐与订单 | `membership_plan`、`membership_order` | 已支持全款购买与补差升级；V1 订单只读，不开放退款 |

### 3.2 当前实现与本设计的差距

1. `web-admin` 当前没有业务代码，且 POM 直接依赖 `web-app`，需要调整为独立应用。
2. 后台管理员使用独立的 `admin_account`，不复用 App 用户账号。
3. 题库缺少稳定的草稿、已发布、已下架状态。
4. 面试题当前没有图片字段。
5. 题目排序目前部分读取题目表自身的 `sort_order`，不适合题库关系排序。
6. Comment 只有逻辑删除字段，无法清晰区分隐藏、删除和恢复。
7. 当前会员台账只有到期时间，需要补充暂停、人工发放和永久回收的变更记录。
8. 当前累计计数无法直接生成全部“每日 + 累计”看板指标。
9. 缺少管理员操作日志和题目导入任务记录。

## 4. 总体架构

### 4.1 模块边界

```text
后台前端
   │
   │ 独立 Admin Token
   ▼
web-admin（/api/admin/**）
   ├── 管理员认证与鉴权
   ├── 内容运营
   ├── 用户与社区治理
   ├── 会员运营
   ├── 数据看板
   └── 操作审计
          │
          ▼
  common + model + 可复用领域服务
          │
          ▼
       MySQL / 对象存储 / 支付渠道
```

### 4.2 后端模块规则

- `web-admin` 是独立 Spring Boot 应用，拥有自己的启动类、配置、鉴权拦截器和异常处理入口。
- `web-admin` 依赖 `common`、`model`，不直接依赖 `web-app`。
- 会员发放和会员回收等存在复杂不变量的逻辑，应抽取为可复用领域服务，用户端和管理端不得各写一套计算规则。
- 管理接口统一使用 `/api/admin/**`，用户接口继续使用 `/api/app/**`。
- Admin Token 与 App Token 使用不同的密钥或不同的 `audience`，两种 Token 不可互换。
- 所有写操作在服务端进行权限校验，前端隐藏按钮不能代替鉴权。

## 5. 管理员、认证与权限

### 5.1 角色

#### 超级管理员

- 系统部署时初始化唯一内置账号。
- 拥有全量功能权限和数据权限。
- 可以邀请、冻结、归档普通管理员并配置其权限。
- 独占永久封禁用户、永久回收会员、套餐配置等高风险权限。
- 不可被冻结、归档、删除或降级。
- 不允许通过后台再创建第二个超级管理员。

#### 普通管理员

- 只能由超级管理员通过邮箱邀请创建。
- 无自助注册入口。
- 默认获得内容运营、用户临时禁用和社区治理权限。
- 会员发放、暂停和恢复权限由超级管理员按需授予。
- 永远不能获得永久封禁、永久回收会员、套餐配置和管理员管理权限。

### 5.2 管理员账号状态

| 状态 | 含义 | 是否可登录 |
| --- | --- | --- |
| `INVITED` | 预留状态；V1 的待接受邀请实际保存在邀请记录中 | 否 |
| `ACTIVE` | 正常使用 | 是 |
| `DISABLED` | 被超级管理员冻结 | 否 |
| `ARCHIVED` | 已从组织移除，仅保留历史归属 | 否 |

管理员不做物理删除。归档后的管理员名称和 ID 继续保留在历史操作日志中。

### 5.3 邀请与登录流程

1. 超级管理员填写被邀请人的邮箱、显示名称、功能权限和数据范围。
2. 系统生成一次性邀请令牌，并直接向后台返回可复制的邀请链接；V1 不接入 SMTP，也不自动发送邮件。
3. 邀请链接默认 24 小时失效，且只能使用一次。
4. 接受邀请前只保存邀请记录，不提前创建管理员账号；被邀请人设置密码后创建 `ACTIVE` 账号。
5. 邀请过期后由超级管理员重新生成链接。
6. 密码只保存强哈希，不保存或发送明文密码。
7. 管理员被冻结、归档、重置密码或回收权限后，现有登录会话立即失效。

超级管理员的初始凭据通过部署环境安全注入，首次登录必须修改密码。

### 5.4 权限模型

V1 不建立自定义角色表。普通管理员权限由“固定身份 + 权限码 + 数据范围”组成。

#### 功能权限

| 权限域 | 主要能力 | 普通管理员默认 |
| --- | --- | --- |
| `dashboard` | 查看被授权范围内的看板 | 是 |
| `bank` | 查看、创建、编辑、发布、下架、删除、恢复题库 | 是 |
| `question` | 查看、创建、编辑、导入、发布、下架、删除、恢复、排序题目 | 是 |
| `user.view` | 查询用户及用户详情 | 是 |
| `user.disable` | 临时禁用和恢复用户 | 是 |
| `user.ban` | 永久封禁和解除永久封禁 | 否，仅超级管理员 |
| `community.moderate` | 隐藏、删除、恢复 Post 和 Comment | 是 |
| `community.restrict` | 暂停和恢复用户发帖评论权限 | 是 |
| `membership.view` | 查看会员、台账和订单 | 由超级管理员逐个配置 |
| `membership.grant` | 人工发放或延长会员 | 由超级管理员逐个配置 |
| `membership.suspend` | 暂停和恢复会员权益 | 由超级管理员逐个配置 |
| `membership.revoke` | 永久回收会员 | 否，仅超级管理员 |
| `membership.plan` | 新建、改价、上架、下架套餐 | 否，仅超级管理员 |
| `admin.manage` | 邀请和管理普通管理员 | 否，仅超级管理员 |
| `audit.view` | 查看审计日志 | 只能查看自己；超级管理员查看全部 |
| `audit.export` | 导出审计日志 | 否，仅超级管理员 |

#### 数据范围

内容权限支持两种范围：

- `ALL_BANKS`：可管理全部题库及其题目。
- `ASSIGNED_BANKS`：只能管理超级管理员分配的题库。

创建新题库的管理员自动获得该题库的数据权限。用户、社区和会员数据 V1 不划分组织范围，只有获得对应功能权限后才能查看全量数据。

### 5.5 权限安全规则

- 普通管理员不能修改自己的权限和数据范围。
- 普通管理员不能对超级管理员执行任何账号操作。
- 超级管理员修改他人权限时必须填写原因。
- 高风险操作必须再次输入当前管理员密码或通过等价的二次校验。
- 服务端每次请求都读取有效管理员状态；被冻结账号的旧 Token 不得继续使用。

## 6. 信息架构

| 一级导航 | 二级页面 | 主要用途 |
| --- | --- | --- |
| 数据看板 | 全局概览、题库排行 | 每日与累计运营指标 |
| 内容管理 | 题库管理、题目管理、导入任务 | 内容生产、发布和排序 |
| 用户治理 | 用户管理、社区内容、社区限制 | 账号和社区治理 |
| 会员管理 | 会员列表、订单列表、套餐管理 | 权益、订单查询和商品配置 |
| 系统管理 | 管理员管理、操作日志 | 权限和审计 |

菜单和页面由权限决定是否展示；无权限访问页面时，后端仍必须返回拒绝访问。

## 7. 数据看板

### 7.1 页面结构

数据看板由以下区域组成：

1. 今日核心指标卡
2. 最近 7 天或 30 天趋势
3. 题库表现排行
4. 会员转化概览
5. 数据更新时间和统计口径说明

### 7.2 指标口径

系统统计时区固定为 `Asia/Singapore`，自然日为本地时间 `00:00:00` 至次日 `00:00:00`。

| 指标 | 每日口径 | 累计口径 |
| --- | --- | --- |
| 题库浏览 | 当日进入题库内容页的 PV | 历史浏览 PV |
| 题库完成人数 | 当日首次完成该题库的去重用户数 | 历史完成该题库的去重用户数 |
| 登录人数 | 当日至少成功登录一次的去重用户数 | 历史至少成功登录一次的去重用户数 |
| 注册人数 | 当日新建且注册完成的用户数 | 当前累计注册用户数，包含被禁用和封禁用户 |
| 发帖人数 | 当日至少发布一条 Post 的去重用户数 | 历史至少发布过一条 Post 的去重用户数 |
| Premium 新付费人数 | 当日第一次成功付费购买 Premium 的去重用户数 | 历史付费购买过 Premium 的去重用户数 |
| Premium Plus 新付费人数 | 当日第一次成功付费购买 Premium Plus 的去重用户数 | 历史付费购买过 Premium Plus 的去重用户数 |
| 当前有效会员 | 当下权益有效的用户数快照 | 不做累加 |

补差升级计入 Premium Plus 付费行为，但同一用户同一天重复购买只计一个付费人数。订单数和收入不等于付费人数，应作为后续独立指标。

### 7.3 数据更新规则

- 今日指标允许分钟级更新，目标延迟不超过 5 分钟。
- 已结束自然日的数据由定时任务汇总并固化。
- 累计值不得简单累加每日 UV，必须按历史去重口径计算或由可靠累计表维护。
- 删除 Post 不回写历史“发帖用户”指标；当前有效会员随双台账到期和管理员调整变化。
- 页面必须显示最近更新时间；统计异常时展示“数据更新中”，不能用 0 冒充真实值。

### 7.4 数据范围

- 超级管理员查看全站数据。
- `ALL_BANKS` 普通管理员查看全站题库指标。
- `ASSIGNED_BANKS` 普通管理员只查看已分配题库的指标。
- 用户、社区、会员指标还需同时具备对应查看权限，否则不显示相应卡片。

## 8. 题库管理

### 8.1 列表

题库列表支持以下筛选：

- 题库 ID 或题库名称
- Group、Module、SubModule 级联分类
- 业务状态
- 创建人
- 创建时间、发布时间

列表展示题目数量、发布题目数量、累计浏览量、完成人数、优先级和更新时间。统计字段只读，不能通过编辑表单直接修改。

### 8.2 创建

题库只能单条创建。创建字段如下：

| 字段 | 规则 |
| --- | --- |
| Group | 必选，只能从已有数据选择 |
| Module | 必选，根据 Group 级联选择 |
| SubModule | 必选，根据 Module 级联选择 |
| 题库名称 | 必填，去除首尾空格后全局唯一 |
| 标签 | 可选，使用现有 `bank_tag` 关系 |
| 优先级 | 可选，默认 0，数值越大展示优先级越高 |
| 初始状态 | 固定为 `DRAFT` |

数据库只保存最终的 `sub_module_id`。Group 和 Module 是选择上下文，不冗余写入题库表。

### 8.3 生命周期

```text
DRAFT ──发布──> PUBLISHED ──下架──> OFFLINE
  ▲                    └──重新发布──┘
  └────────恢复已删除记录后回到原非发布状态
```

| 状态 | 前台可见 | 可编辑 | 可删除 |
| --- | --- | --- | --- |
| `DRAFT` | 否 | 是 | 是 |
| `PUBLISHED` | 是 | 是 | 否，需先下架 |
| `OFFLINE` | 否 | 是 | 是 |

发布题库前至少存在一条已发布题目。首次发布写入 `published_time`，后续重新发布不覆盖首次发布时间。

### 8.4 编辑与删除

- 支持编辑名称、所属 SubModule、标签和优先级。
- 修改分类时只更新题库的 `sub_module_id`；题目自身不保存分类层级，因此不执行“同步更新所有题目分类”的冗余操作。
- 有题目的题库只能在同一 Group 内调整 Module 或 SubModule，不能直接在面试与认证分类之间迁移。
- 已发布题库的名称、标签和优先级保存后即时对前台生效。
- 已发布题库变更所属分类属于高影响操作，需要二次确认。
- 删除为逻辑删除，必须填写原因。
- 删除题库不级联删除题目、答题记录、收藏、笔记或统计数据。
- 恢复题库后默认保持不可见状态，需要重新发布。
- V1 不提供任何题库批量写操作。

## 9. 题目管理

### 9.1 题目域与题型

题库所属 Group 决定题目存储和允许题型：

| Group | 数据模型 | 允许题型 | 正确答案规则 |
| --- | --- | --- | --- |
| `INTERVIEW` | `question_info` | `ESSAY` | 无标准选项，使用参考答案和 AI 评价 |
| `CERTIFICATION` | `certificate_question_info` | `SINGLE_CHOICE` | 必须且只能有一个正确选项 |
| `CERTIFICATION` | `certificate_question_info` | `MULTIPLE` | 必须有两个或以上正确选项 |

V1 不支持判断题。若需要判断题，应先扩展枚举、数据校验、答题页和结果判定，再纳入后台。

### 9.2 创建字段

所有题型共有字段：

- 所属题库
- 题目标题
- 题目图片，可选
- 答案解析或参考答案
- 题目类型
- 发布状态

选择题额外包含：

- 备选项，至少 2 个
- 选项标识，由系统按 `A、B、C...` 生成
- 正确选项

面试题的“答案解析”在产品展示中称为“参考答案”，底层继续使用现有 `analysis` 字段。

### 9.3 图片规则

- 单题最多一张题干图片。
- 支持 JPG、PNG、WebP。
- 单文件不超过 5 MB。
- 上传成功后只保存腾讯云 COS 对象 Key，不把公开地址或临时签名地址写入数据库。
- 存储桶保持私有读写；管理端和 App 端在已通过业务权限校验后，按需生成 1 小时有效的只读签名 URL。
- 题目保存失败时保留未绑定的临时文件，由对象存储生命周期规则或后续清理任务删除。
- 替换图片时，先保存新数据，再异步清理旧图片，避免保存失败导致原图丢失。
- 为满足面试题图片需求，需要给 `question_info` 补充 `image_object_key`。

### 9.4 题目绑定

- 单条创建和批量导入前必须先选择题库。
- 题型必须与题库 Group 匹配。
- V1 新建题目时只创建一条目标题库关系，暂不提供“关联已有题目到其他题库”的操作入口。
- `question_bank_question` 继续作为多对多关系表，不给 `question_id` 增加单列唯一约束。
- 同一题目不能重复加入同一题库，关系唯一性由 `(bank_id, question_id)` 保证。
- 面试题只能关联面试题库，认证题只能关联认证题库。
- 从某个题库移除题目时只解除该题库关系；题目仍被其他题库引用时，不得删除题目主体。
- 如果数据库中已经存在被多个题库引用的题目，只有拥有全部关联题库数据权限的管理员才能修改题目主体；V1 对其他管理员拒绝编辑，未来开放一题多库操作时再提供“复制为新题目”能力。

### 9.5 发布、下架、删除与恢复

管理员不直接编辑底层 `isReleased` 或 `isDeleted` 字段，而是执行有业务含义的操作：

| 操作 | 数据效果 | 前台效果 |
| --- | --- | --- |
| 发布 | `is_released=true` | 可被前台读取 |
| 下架 | `is_released=false` | 不再出现在新请求中 |
| 删除 | 逻辑删除并记录原因 | 不可见，可在后台回收站查询 |
| 恢复 | 清除逻辑删除，保持未发布 | 恢复后仍需人工发布 |

已进入认证考试 Session 的题序为开始考试时的快照。题目下架或排序变化不修改已经进行中的考试，只影响新建 Session。

### 9.6 编辑校验

- 标题不能为空。
- 选择题选项文本不能为空，选项标识不能重复。
- 单选题只允许一个正确选项。
- 多选题至少两个正确选项，且正确选项必须存在于备选项中。
- 面试题不允许保存备选项和正确选项。
- 已发布题目修改题干、选项或正确答案时必须二次确认。
- 保存题目和题库关系必须在同一事务中完成。

认证题 V1 继续使用 `certificate_question_info.options` 和 `correct_answer` 作为唯一选项数据源，不同时维护 `question_option`，避免双写不一致。

### 9.7 排序

- 排序入口位于某一题库的“排序模式”。
- 只有具备该题库数据权限的管理员才能排序。
- 拖拽放下后一次性提交最终顺序，不在拖动过程中持续写数据库。
- `question_bank_question.sort_order` 是题库内排序的唯一数据源。
- 保存必须是原子操作，不能出现部分题目更新成功。
- 前台普通练习和面试题展示按该顺序读取。
- 认证考试模式继续在创建 Session 时随机排序，不使用运营排序。

### 9.8 Excel 批量导入

批量导入采用“下载模板 → 上传预检 → 确认导入 → 查看结果”的两阶段流程。

#### 导入规则

- 仅支持 `.xlsx`。
- 单次最多 1,000 行，文件不超过 10 MB。
- 上传前必须选择目标题库。
- 模板根据面试题或认证题分别生成。
- 新导入题目默认未发布。
- Excel 可填写已上传图片的 URL，不解析单元格内嵌图片。
- 同一文件重复提交时通过文件摘要和任务标识阻止重复导入。

#### 预检内容

- 必填字段
- 题型是否合法
- 选项和正确答案是否合法
- 行内和文件内重复
- 字段长度
- 图片 URL 格式
- 目标题库状态和管理员数据权限

预检完成后展示总行数、可导入行数、错误行数和逐行错误原因，并支持下载错误报告。

#### 提交策略

- 存在任一错误行时，整个任务不可确认导入。
- 所有行通过后才允许确认。
- 确认导入采用事务或可靠分批事务；最终状态必须明确为成功或失败，不能把部分成功显示成整体成功。
- 导入任务保存操作者、目标题库、文件摘要、结果统计和失败原因。

## 10. 用户管理

### 10.1 用户列表与详情

列表支持按用户 ID、账号编号、显示名称、账号状态、注册时间和会员状态筛选。

用户详情包含：

- 基础资料和注册时间
- 账号状态及变更历史
- 当前社区限制
- 当前会员等级及双台账到期时间
- 最近订单
- 发帖、评论和学习摘要
- 相关管理员操作日志

邮箱、第三方身份标识等敏感信息按最小必要原则脱敏展示。

### 10.2 账号状态

| 状态 | 规则 |
| --- | --- |
| `ACTIVE` | 正常登录和使用全部已授权功能 |
| `DISABLED` | 临时禁用，不能登录；可由有权限的普通管理员恢复 |
| `BANNED` | 无自动恢复时间的永久封禁；只能由超级管理员设置或解除 |

状态变更必须填写原因。`BANNED` 的“永久”表示不会自动解除，不表示数据不可恢复。

普通管理员只能执行 `ACTIVE ↔ DISABLED`。超级管理员可以执行涉及 `BANNED` 的转换。

V1 不允许删除用户，也不允许修改用户 ID、账号编号或第三方登录身份。

### 10.3 社区权限限制

社区权限限制与登录状态分离：

- `POST`：禁止发布 Post。
- `COMMENT`：禁止评论和回复。
- `BOTH`：同时禁止发布和评论。

限制记录包含开始时间、结束时间、原因、状态和操作者。到期后自动失效。社区限制不影响登录、刷题、会员查看和历史内容浏览。

若账号为 `DISABLED` 或 `BANNED`，账号状态优先于社区限制。

## 11. 社区内容治理

### 11.1 Post 管理

管理员可以按 Post ID、用户、状态、发布时间和关键词筛选。

支持以下操作：

- 隐藏：从公共时间线移除，可恢复。
- 恢复：将隐藏内容恢复为已发布。
- 删除：标记为已删除，保留审计和消息引用。

隐藏或删除 Post 后，其 Comment 不再公开显示，但不级联删除。恢复 Post 时，只恢复仍处于正常状态的 Comment。

### 11.2 Comment 管理

管理员可以按 Comment ID、Post ID、用户、时间和关键词筛选。

- 删除父 Comment 时保留子回复，前台显示“原评论已删除”。
- 恢复父 Comment 后恢复原正文展示。
- 删除或恢复必须正确更新 Post 的有效评论数，且重复请求不能重复加减。
- 已生成的历史通知保留，但正文按内容当前可用性降级展示。

为实现统一、可恢复的治理流程，建议给 Comment 增加 `PUBLISHED`、`HIDDEN`、`DELETED` 业务状态，而不是让管理员直接操作通用 `is_deleted`。

### 11.3 治理操作规则

- 每次操作必须选择或填写原因。
- 内容操作对用户端的新请求即时生效。
- 恢复操作不得恢复其作者已经主动删除的内容。
- 后台内容列表默认不显示正文中的潜在敏感信息全文，查看详情后再展示。

## 12. 会员、订单与套餐

### 12.1 会员模型

- Premium 对应 `base_vip_record`。
- Premium Plus 对应 `svip_record`。
- Premium Plus 有效时优先生效，Premium 剩余时长继续保存在基础台账中。
- 后台所有人工调整必须复用用户端相同的双台账计算规则。

### 12.2 会员列表与详情

支持按用户、当前会员等级、权益状态和到期范围筛选。

详情包含：

- 当前生效等级
- Premium 与 Premium Plus 各自到期时间
- 是否存在会员暂停
- 订单历史
- 人工发放、暂停、恢复和回收记录
- 每次变更前后的台账快照

### 12.3 管理动作

| 动作 | 普通管理员 | 超级管理员 | 规则 |
| --- | --- | --- | --- |
| 人工发放或延长 | 授权后可用 | 可用 | 选择等级和时长，必须填写原因 |
| 暂停权益 | 授权后可用 | 可用 | 暂停期间到期时间继续流逝 |
| 恢复权益 | 授权后可用 | 可用 | 只移除暂停状态，不补偿时长 |
| 永久回收 | 不可用 | 可用 | 回收全部当前会员权益 |

“暂停权益”是访问控制，不是冻结会员时钟。若未来需要补偿暂停天数，应作为单独需求设计。

### 12.4 人工调整规则

- 不允许管理员在页面直接填写或覆盖数据库到期时间。
- 人工发放使用明确的会员等级和时长档位。
- 每次操作记录原因、变更前快照和变更后快照，并通过台账版本避免并发覆盖。
- 修改 Premium Plus 时必须同时遵守 Premium 冻结和续期规则。
- 对同一用户的会员变更必须锁定相关双台账，避免并发覆盖。

### 12.5 退款边界

V1 不提供退款权限、接口、记录表和支付渠道调用。订单页面只做查询。未来需要退款时，应单独设计退款状态机、支付渠道幂等、会员流水重算和异常补偿，不能直接在本版本的订单动作中追加简单退款逻辑。

### 12.6 套餐管理

超级管理员可以：

- 新建套餐
- 修改价格
- 上架或下架

已产生订单的套餐，其会员等级、购买类型、计费周期、时长和币种不可原地修改。需要改变这些结构字段时，应下架旧套餐并创建新套餐。历史订单继续使用下单时快照。

## 13. 操作日志

### 13.1 必须记录的操作

- 管理员邀请、权限变更、冻结和归档
- 题库创建、编辑、发布、下架、删除和恢复
- 题目创建、编辑、导入、发布、下架、删除、恢复和排序
- 用户禁用、恢复、封禁和解封
- 社区限制和内容治理
- 会员发放、暂停、恢复和回收
- 套餐创建、改价、上架和下架

### 13.2 日志内容

每条日志至少包含：

- 操作 ID
- 操作时间
- 管理员 ID 和显示名称快照
- 操作模块和动作
- 目标类型和目标 ID
- 变更前与变更后摘要
- 操作原因
- 请求 ID
- IP 和 User-Agent
- 执行结果及失败原因

密码、Token、支付密钥、完整第三方身份凭证等敏感字段不得写入日志。

### 13.3 日志规则

- 日志只追加，不允许后台修改或删除。
- 业务操作和日志应尽量在同一事务中落库；外部支付操作则记录每个状态变化。
- 普通管理员只能查看自己的日志。
- 超级管理员可以查询和导出全部日志。
- 导出本身也必须产生操作日志。

## 14. 异常、并发与一致性

- 所有写操作都要校验目标是否存在、当前状态是否允许转换、操作者是否有权限。
- 删除、恢复、发布、下架和会员变更应通过状态与版本校验避免重复生效。
- 题目编辑、排序、会员变更等可能并发的操作应使用版本号或行锁避免丢失更新。
- 页面提交时若数据已被他人修改，返回冲突并要求刷新，不静默覆盖。
- 数据库事务只覆盖本地数据；文件存储等外部操作使用明确的任务状态和补偿机制。
- 导入、导出和大范围统计使用异步任务，页面可以查询进度和结果。

## 15. 安全要求

- 管理后台与用户网站使用不同域名或至少不同 Cookie/Token 存储空间。
- 登录失败需要限流；连续失败达到阈值后临时锁定。
- 管理员密码重置、冻结、归档和权限回收后立即使旧会话失效。
- 邀请令牌、重置令牌为一次性、短时有效且数据库只保存摘要。
- 所有管理端请求使用 HTTPS。
- 上传文件校验扩展名、MIME、文件头和大小。
- Excel 内容按纯数据解析，禁止执行公式或宏。
- 用户隐私字段和支付数据按权限脱敏。
- 生产环境禁止通过日志输出请求体中的密码、Token 或支付敏感信息。

## 16. 建议新增或调整的数据能力

以下是业务设计所需的数据能力，不是最终 DDL：

| 数据能力 | 用途 | 优先级 |

| 管理员操作日志 | 全部后台写操作审计 | P0 |

| 用户社区限制记录 | 独立控制发帖和评论 | P0 |
| 题目导入任务与错误明细 | 两阶段批量导入 | P0 |

## 18. V1 验收标准

### 权限

- 用户端 Token 无法访问任何管理接口。
- 普通管理员无法通过构造请求执行超级管理员专属操作。
- 数据范围为 `ASSIGNED_BANKS` 时，列表、详情和写操作均不能越权。
- 冻结或归档管理员后，其旧会话立即失效。

### 内容

- 题库只能单条创建，名称重复时拒绝保存。
- 发布题库前必须至少有一条已发布题目。
- 面试题和认证题题型不能交叉创建。
- 选择题的选项与正确答案校验完整。
- Excel 有错误行时不会写入任何题目。
- 拖拽排序保存后，普通练习读取新顺序；进行中的认证考试不受影响。

### 用户与社区

- 普通管理员只能临时禁用用户，不能永久封禁。
- 社区限制不影响刷题和会员读取。
- 删除父 Comment 后子回复保留。
- 内容恢复不会错误恢复用户主动删除的内容。

### 会员

- 人工调整不能绕过双台账规则。
- 暂停期间会员时钟继续流逝，恢复后不自动延长。
- 订单管理没有退款入口，任何管理员都不能从 V1 发起退款。

### 审计与统计

- 每个后台写操作都能通过请求 ID 找到对应操作日志。
- 日志中不出现密码、Token 和支付密钥。
- 每个看板指标都能展示口径和最近更新时间。
- 每日 UV 与累计 UV 不通过简单求和得到。

## 19. 已确认的产品决策

以下规则已于 2026-07-26 确认：

1. 后台管理员使用独立账号表，不复用 `user_info`。
2. V1 题型只包含简答、单选和多选，暂不增加判断题。
3. 分类树 V1 只读，题库只能单条创建。
4. V1 暂不提供将已有题目关联到其他题库的入口，但 `question_bank_question` 保留一题多库能力；题库内排序统一保存在关系表的 `sort_order`。
5. 会员暂停期间到期时间继续流逝，恢复后不补时长。
6. V1 暂不开放退款，不提供退款权限、接口或支付渠道调用。
7. 普通管理员默认拥有内容运营和临时用户治理权限；其会员管理权限由超级管理员逐个配置，默认不开放。
8. 后台管理员需要浏览 App 时，使用普通 App 账号，并由有权限的管理员给对应 `user_info.id` 正常发放会员；后台身份不绕过会员校验。

管理端接口文档、DTO/VO、权限注解、错误码和数据库迁移设计以本节为固定输入。
